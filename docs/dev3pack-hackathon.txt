Overall rules

   Team size: maximum 4 members. Teams are formed in the dashboard, and a join code is shown there.
   Multiple tracks: one project may apply to several tracks, but the same project cannot win twice.
   Open source is mandatory: "Yes, your project must be open source. Projects that are not open source
   will not be considered for prizes."
   Starting early is allowed: you may use your own previously created projects, but ideally the project
   should be new or at least significantly improved during the hackathon.
   AI tools are allowed: "Yes, you can use AI tools like Cursor, Claude, ChatGPT, or v0 to build your
   project. The best projects use AI tools to ship faster."
   AI credits: an FAQ titled "How do I claim my AI credits?" exists on the overview page. The Resources
   page lists the tools covered later in this document, and an "Use AI credits" link.
   Sponsor tools must be core: on every sponsor track, the tool has to power a core feature of the app,
   not a side feature or bolt-on, and the open-source README must explain that integration.

How judging works

For the Solana tracks, the prizes page states that judges look for:

   A real, working product with clean UI/UX.
   Live on-chain transactions that the judges can test.
   A clear problem and solution.
   A team of hackers who built it during the hackathon.

Each track below also lists its own judging criteria where the dashboard shows them.

What a submission must contain

The submit project form has 5 steps: 1. Project details, 2. Images, 3. Links and video, 4. Team, 5. Review
and submit. All fields marked with * are required.

Step 1: Project details
   Project name (required)
   Tagline (required, max 60 characters)
   Description (required)
   Category (required): DeFi, Consumer, Gaming, AI, Payments, Infrastructure, Education, Social, or Other
   Track (required): choose from all global and local tracks
   Project status (required): Prototype, Beta, or Live
   Programming languages (required)
   Frameworks (required)

Steps 2 to 5 could not be inspected without completing Step 1, so their exact required fields, such as whether a video or
live deployment URL is mandatory on the form itself, are not confirmed from the form. The Solana track text does
require a video demo and a deployed program. Required integrations also depend on the track you enter.

Global tracks 1 to 3: Solana


 1. Solana - Best App Overall on Solana
   $5,000 - Sponsor: Solana

 "This track is for the best app overall on Solana, across all types of applications. Create an open-
 source app on Solana. You can build whatever you want, from a killer DeFi product, to consumer app,
 to a game, to a developer tool. Surprise us."

 What to build: a real, usable app on Solana, presented with a video. Judging: innovation, UX,
 working product, real use case.

 Ideas: DeFi protocol or dashboard; AI x Crypto agent; consumer app (social, marketplace, creator
 tools); payments app; gaming app; infra or dev tool.

 Qualification requirements:

    Deployed Solana program on mainnet or devnet, built with Anchor or native Rust. If the app
    genuinely does not need a custom program, for example a wallet or payments app, it must still
    have a real, working on-chain transaction.
    The program is used: integrated into the app's core flow and invoked by real users, not just
    deployed.
    Wallet support: connect a Solana wallet and interact with the app.
    Token management: create, mint, transfer and use tokens; manage balances and token
    operations.
    Transaction details: show transaction signatures, status, and history inside the app.
    A video demo must show the app working end-to-end with real on-chain transactions.
    Open-source repo: README with setup, demo video, and the program ID. The demo must use
    mainnet or devnet.

 What gets rejected: a demo built entirely with mock data; a program deployed but never called; a
 template fork with cosmetic changes; a landing page with no working product; a video that only shows
 slides.
